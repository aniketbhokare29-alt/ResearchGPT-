# Paper processing and models

## Ingestion flow

1. An accepted PDF record and its generated storage path are committed first.
2. A background task opens the PDF with PyMuPDF and extracts text separately for each page.
3. Text is normalized; available title, author, abstract, and publication-year metadata are extracted.
4. Page text is split into overlapping word chunks. Each chunk stores its source page range and approximate token count.
5. Sentence Transformers embeds each chunk on CPU by default, or on CUDA when `MODEL_DEVICE=auto` detects a GPU.
6. Chunks and their normalized embedding vectors are stored in the database. A per-user persistent vector file is updated atomically; FAISS creates an exact inner-product index where its package is available. Windows uses an exact NumPy cosine search fallback.
7. The status moves through pending, running, and completed, or failed with an error that can be retried from the paper detail page.

An upload is not considered processed until text and vectors are stored and indexed. Paper deletion and reprocessing remove or replace the associated chunk vectors. If a vector index file is missing, it can be rebuilt from persisted chunk embeddings.

## Summaries

Summary generation is a separate background task so PDF upload and indexing do not wait for the summarization model. The configured pretrained Transformers summarizer runs a hierarchical map-reduce flow: it summarizes model-sized text windows, then reduces their summaries. This supports long papers without silently truncating the whole paper.

Structured fields such as objectives, methods, datasets, results, limitations, and future scope are selected from extracted paper sections and sentences. Missing evidence is labeled as not stated. The overview is generated by the configured model and may require model weights to be downloaded on first use.

## Configuration

See `.env.example` for `EMBEDDING_MODEL_NAME`, `SUMMARY_MODEL_NAME`, `MODEL_DEVICE`, chunk size and overlap, and model batch/context settings. A local model cache is used by Hugging Face Transformers and Sentence Transformers. A missing or unloadable model sets the relevant job to failed and returns a visible error; the app does not substitute hardcoded summary text.

Scanned/image-only PDFs are marked failed with an OCR-required message. OCR is not included in this phase.
